# โปรเจกต์แอปทำนาย Conversion — ทีมจี้จ่อเจี๊ยบ (ใบงานสัปดาห์ที่ 12)

แอป **Streamlit** เวอร์ชันแรกที่ห่อ _"โมเดลสุดท้ายของทีม"_ ให้คนอื่นกดใช้ได้
ต่อยอดจากโครงงาน **AI วิเคราะห์พฤติกรรมผู้เข้าเว็บที่มีแนวโน้มทำให้เกิด Conversion**
(ข้อมูล `online_shoppers_intention` · Kaggle: henrysue/online-shoppers-intention)

## ไฟล์ในโปรเจกต์

| ไฟล์ | หน้าที่ |
|---|---|
| `app.py` | **แอปหลัก (งานกลุ่ม)** — โหลดโมเดลสุดท้ายของทีม + ฟอร์ม 2 ฟีเจอร์ + คำแนะนำเชิงธุรกิจ |
| `team_model.joblib` | โมเดลสุดท้ายของทีม: `DecisionTreeClassifier(max_depth=5, random_state=42)` |
| `team_features.json` | รายชื่อฟีเจอร์ + ค่า min/max เดิม (ก่อนสเกล) + ความแม่นของโมเดล |
| `app_titanic_stepB.py` | แอปตัวอย่างงานเดี่ยว (ภาค B ขั้น 1–7) ที่ใช้โมเดล Titanic ฝึกมือก่อนสลับเป็นโมเดลทีม |

| `requirements.txt` | ไลบรารี + เวอร์ชันที่ใช้จริง (ล็อกไว้ให้ตรงกับตอนบันทึกโมเดล) |
| `run.bat` | ดับเบิลคลิกเพื่อเปิดแอป |
| `PROMPT_LOG.md` | สรุป prompt ที่ใช้สั่ง Claude ตอนสร้างแอป (ตามที่ใบงานกำหนด) |
| `venv/` | Virtual environment ของโปรเจกต์ |

## โมเดลและฟีเจอร์

- **โมเดลสุดท้ายของทีม:** `DecisionTreeClassifier(max_depth=5, random_state=42)`
  (เลือกจากตารางเทียบ 4 โมเดลในสัปดาห์ที่ 5–11 — ดู `final_model_decision` ในรายงานใบงานสัปดาห์ที่ 11)
- **ฟีเจอร์ input (ตรงกับ `best_features.json` สัปดาห์ที่ 10 ไม่ขาดไม่เกิน):**
  1. `ProductRelated_Duration` — เวลาที่อยู่หน้าสินค้า (วินาที)
  2. `PageValues` — มูลค่าเพจที่ผู้ใช้ดู
- **การสเกล:** ข้อมูลถูก MinMax สเกล 0–1 ตั้งแต่สัปดาห์ที่ 3 → แอปสเกล input ด้วยสูตร
  `(ค่าที่กรอก − min) ÷ (max − min)` โดยใช้ค่า min/max เดิมจากข้อมูลดิบ
  (`PageValues` 0–361.76, `ProductRelated_Duration` 0–63,973.52)
- **ความแม่น:** test accuracy 0.8943 · 5-fold CV 0.8844 (ข้อมูล 12,205 แถว)
- **ความหมายผลลัพธ์:** `1 = เกิด Conversion (ลูกค้าซื้อ)` · `0 = ไม่เกิด Conversion` · เกณฑ์ตัดสินใจ 0.5

## ข้อจำกัดของโมเดล (ควรบอกผู้ใช้ก่อนนำไปใช้จริง)

1. **ข้อมูลคลาสไม่สมดุล** — Conversion มีเพียง ~15.6% ของข้อมูล ทำให้ค่าความแม่นรวมดูสูง
   แต่ความแม่นของคลาส "Conversion" อยู่ที่ precision 0.69 / recall 0.59 เท่านั้น
   (คือพลาดเคสที่ซื้อจริงไปพอสมควร) จึงควรใช้เป็น "ตัวช่วยจัดลำดับความสำคัญ" ไม่ใช่ตัวตัดสินใจสุดท้าย
2. **ใช้แค่ 2 ฟีเจอร์** — GA (สัปดาห์ที่ 10) คัดเหลือ 2 ฟีเจอร์เพื่อความประหยัด
   ถ้าต้องการความแม่นสูงสุดควรใช้ทั้ง 28 ฟีเจอร์ (baseline accuracy 0.8940)
3. **ช่วงค่าที่รับ** — ฟอร์มจำกัดค่าให้อยู่ในช่วงเดียวกับข้อมูลที่ใช้เทรน
   ถ้ากรอกนอกช่วง โมเดลจะทำนายแบบ extrapolate ซึ่งเชื่อถือได้น้อยลง
4. **เป็นเวอร์ชันแรกสำหรับรันในเครื่อง** — ยังไม่ได้ deploy ขึ้น cloud (กำหนดทำสัปดาห์ถัดไป)
5. ไม่ได้ใช้ข้อมูลส่วนบุคคลของลูกค้าจริง — ข้อมูลที่ใช้เป็นชุดสาธารณะจาก Kaggle
